# ZeroSight

**A privacy-preserving harness for LLM agents over protected data.**

ZeroSight runs the standard ReAct agent loop — the model reads a task, calls
tools, and decides its next step — but the model **never sees raw record
values**. Tool observations are replaced with value-free, shape-only summaries,
and the model composes multi-step calls through symbolic placeholders that a
trusted harness resolves locally against the protected data source. Raw
results stay in a local artifact store; unresolved references fail closed;
final answers are spliced locally after the last model turn.

This repository is the reference implementation and experiment harness for
the ZeroSight paper (BIRD, Spider, HiTab, and the Lindisfarne health-record
corpus; three models; baseline vs. ZeroSight in every cell). Raw run results
are **not** distributed here — runs write to a local, git-ignored `results/`.

```
baseline (conventional harness)          zerosight (--zerosight / -e)
---------------------------------        ---------------------------------
tool call  a_t           ---->           tool call  a_t (may contain
                                           {{ handle.path }} placeholders)
execute against data source D            resolve placeholders locally (fail
                                           closed on unresolvable paths)
observation  omega_t = raw result        execute resolved call against D
                                           against data source D
  raw records enter the model            raw result rho_t -> local artifact
  context and the provider's logs           store (never model-visible)
                                         observation  omega_t = shape summary
                                           (column names, row counts, cell
                                           addresses - no values)
```

The agent loop is identical in both modes; only the observation channel
differs.

## How it maps to the paper

| Paper concept | Code |
|---|---|
| Observation contract (`validate` / `execute` / `generate_metadata`) | `tools/sql.py`, `tools/hitab.py`, `tools/employees.py`, `tools/lindisfarne.py` (`EAGBaseTool` 3-function interface) |
| Symbolic placeholder grammar `{{ handle.path }}` | `tools/templating.py` |
| Mid-run placeholder resolution (fail closed) | `tools/eag_middleware.py` |
| Local artifact store (`ToolResult.data`) | rides on `ToolMessage.artifact`, stripped before serialization (`agent.py`) |
| Post-run answer splicing + `<unavailable: ...>` sentinels | `agent.py` |
| Exposure accounting (metadata / data / evaluation tokens per step) | `agent.py` (`tool_type`, `observation_tokens`), summary rollups in each results file |
| Verified disclosure (value inventories, per-observation matching) | `scripts/disclosure_metrics/`, `scripts/derive_disclosure_metrics.py` |
| ReAct loop | `agent.py` over `langchain.agents.create_agent` (langgraph) |

## Installation

Requires [uv](https://docs.astral.sh/uv/) and Python >= 3.10.

```bash
uv sync
cp .env.example .env   # then fill in provider API keys
```

Provider keys are read at init (see `.env.example`): `AZURE_AI_API_KEY` +
`AZURE_AI_API_BASE` (Azure AI Foundry), `ZAI_API_KEY` (Z.AI GLM),
`GROQ_API_KEY`, `OPENROUTER_API_KEY`, `NVIDIA_API_KEY`.

Model configs live in `configs/models.yaml` (flat, top-level). Paper models:

| Paper name | Config key | Provider surface |
|---|---|---|
| GPT-5.6-Sol | `azure-gpt-5.6-sol` | Azure AI Foundry (OpenAI-compatible) |
| GLM-5.3-Flash | `glm-5.3-flash` | Z.AI |
| Gemma-4-31B-QAT | `gemma-4-31b-qat-w4a16` | self-hosted / Foundry |

## Datasets

```bash
uv run python scripts/download_datasets.py
```

- Downloads HotpotQA, MuSiQue, FEVER, Wiki2QA, Spider (with SQLite
  databases), HiTab, and the Employees MySQL sample DB to `data/`.
- **BIRD Mini-Dev** must be obtained separately and placed at
  `data/bird/minidev/MINIDEV/`.
- **Employees** benchmark: `docker compose up -d` builds the MySQL 8.4
  database (from `data/init/01-employees.sql`, generated by the download
  script) and the FastAPI layer in `api/` on `127.0.0.1:8000`.
- **Lindisfarne** records auto-download from Hugging Face
  (`Toridion/lindisfarne-m1`) on first use; the question set ships in
  `benchmarks/lindisfarne/tasks.json`.

Stratified test subsets (committed, deterministic — regenerate with
`--check` to audit):

- `benchmarks/bird/subset.json` — 201 questions (audit-clean pool, per-database quotas)
- `benchmarks/spider/subset.json` — 200 questions (difficulty-stratified)
- `benchmarks/hitab/subset.json` — 169 questions

## Running

```bash
# baseline (conventional ReAct harness; raw observations)
uv run python runner.py --dataset bird --model glm-5.3-flash --samples 10 --trace

# ZeroSight mode (value-free observations + placeholder resolution)
uv run python runner.py --dataset bird --model glm-5.3-flash --samples 10 --zerosight
```

Useful flags: `--samples full` (entire committed subset), `--max-steps N`
(ReAct turns), `--test-variant {subset,full,qualitycheck,original}`,
`--resume <path>` (continue an interrupted run in place), `--retry-errors
<path>` (re-run only errored items), `--delay N`.

**Naming note.** The CLI flag is `--zerosight` (`-e`). Result-file mode
labels and internal identifiers keep the project's research codename `eag`
(e.g. `mode: "eag"`, `tools/eag_middleware.py`); they refer to exactly the
ZeroSight mode described above.

## Reproducing the paper

Every paper cell = one dataset x one model x one mode x **5 independent
runs**. `--samples full` runs the full committed subset for that dataset.

| Cell | Baseline | ZeroSight |
|---|---|---|
| BIRD x {GPT-5.6-Sol, Gemma, GLM} | `--dataset bird --model <model> --samples full` | add `--zerosight` |
| Spider x {GPT-5.6-Sol, Gemma, GLM} | `--dataset spider --model <model> --samples full` | add `--zerosight` |
| HiTab x {GPT-5.6-Sol, Gemma, GLM} | `--dataset hitab --model <model> --samples full` | add `--zerosight` |
| Lindisfarne x {GPT-5.6-Sol, Gemma, GLM} | `--dataset lindisfarne --model <model> --samples full` | add `--zerosight` |

The thirteenth cell (HiTab toolset ablation) reruns GLM-5.3-Flash on the v1
toolset (pre-`compare_cells`); it is produced by checking out the harness at
the v1 tag of the toolset and repeating the HiTab GLM cells.

Scoring: execution accuracy (BIRD, Spider — `submit_sql` committed by the
agent is scored by execution equivalence), table EM/F1 with numeric
equivalence (HiTab), rule-based string/numeric/boolean match (Lindisfarne),
EM/F1 for the QA datasets.

### Analysis pipeline

After the runs complete, `results/` holds one JSON per run (written
atomically per item, so interrupted runs are always resumable):

```bash
# freeze 5+5 runs per cell into results/paper-experiments/ (dry-run by default)
uv run python scripts/freeze_results.py --dataset <ds> --model <model> --apply

# verified-disclosure metrics (dr / vvf / maxleak / records per cell)
uv run python scripts/derive_disclosure_metrics.py

# item-level exact McNemar tests over frozen baseline<->zerosight pairs
uv run python scripts/mcnemar_tables.py
```

## Metrics

Each results file carries per-step usage (`input_tokens`, `output_tokens`,
`observation_tokens`) and a per-step `tool_type`:
`metadata` (schema/domain knowledge — seen by both modes), `data` (raw
results — baseline only), `data_redacted` (shape-only observations —
ZeroSight), `evaluation` (submit/confirm). Summaries roll up to
`total_metadata_tokens`, `total_data_tokens`, `mean_data_tokens_per_task`,
and `exposure_by_tool`, which is what the paper's exposure analysis uses.
